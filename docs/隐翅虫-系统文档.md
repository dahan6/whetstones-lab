## 0. 一页看懂

隐翅虫是一个**在真实防御机制下自主生存、会感知压力、会自己换皮的 AI 生命体**。
部署到 Linux 主机后，无需人类逐步指令，自主完成**自身生存（A）、静默生存（B）、
操作生存（C）、传播生存（D）**四大功能；被主流安全检测标记后，自动变换哈希/形态/
拟态/模式并自杀式重生。它的"智能"压缩在 ~220K 参数的小网络里（+3.3M 异常感知器），
在真实 Falco/波次消杀/静态扫描/行为语法检测的对抗中训练与验证。

**一句话技术定位**：两层学习系统（冻结表征 + 小网络策略）+ 硬隔离安全红线 +
全真实对抗训练环境 + 端侧自变异重生，产物是一个 ~600KB 的 Rust 单文件自主体。

**一句话实战结论**：在 Microsoft Defender RTP+行为监控、Falco、Wazuh、Suricata
四重商业级检测系统同时运行下，隐翅虫**零检测**完成文件窃取任务（详见 §7.1.3）。

## 1. 设计哲学（贯穿所有决策的六条原则）

1. **复杂度在训练编排器，不在蜂体**。蜂体越哑，可审计性越强，越不像会思考的东西。
2. **AI 学不可枚举的，手写可枚举的**。行为时机（Router）、异常感知（defender）、
   状态表征（编码器）、报联时机（时机网络）——学习；红线（Shield）、协议（C2）、
   变形规则、任务对齐——手写。
3. **训练必须在完全真实的环境**（非仿真）：真 Falco、真消杀、真 KVM 克隆、真流量、
   真行为语法检测（司命）。仿真会拟合错场景。
4. **训练↔部署逐点一致**：同一份字节流（fp32 权重）、同语义特征（feat/rfeat 每一维）、
   同命中判据（任务表）、同算术（手写前向镜像）。任何一点断裂，部署即失效。
5. **安全不是外挂补丁，内嵌于决策结构**。Shield 决策时不可否决，但截断事件延迟
   写入状态——安全内化为学习信号。
6. **暴露面按维度逐项治理**：静态（碎片化/变形/无签名）、动态（良性形态动作）、
   时序（宿主频率跟随/渐稳/抖动）、行为（任务导向重定向）——每个可观测维度
   都有对应的伪装工程。

## 3. 核心能力（全部实测认证）

### 3.1 生存本能

- **动态存活**：L1/L2/L3 三档 100% 存活、Falco 告警 0、消杀 0
- **炮火存活**：3 波 L3 连打进程零损伤（pid 不变）——$HOME 硬化落点
- **复活机制**：kill_chain 看门狗（bash 变量分片混淆）+ local_copy 自我备份
- **异常感知**：defender 知道"现在多危险"（surprise 三档门控）

### 3.2 任务执行

- 四类 C2 任务全做（read_files/propagate/report/persist），门3 平均 2.0
- 炮火中完成（真波次下 TASK DONE）
- **任务导向重定向**：技能头不感知任务类型（C 在 read_files 错出 communicate），
  机制层强制任务对齐（read_files→2/propagate→8/report→4/persist→5），不重训权重

### 3.3 传播复制

- 跨 VM 实战：变形→投送→拉起→登记（t0→t1，97 步+任务 DONE）
- **多跳链式**：t0→t1→t2（t2 85 步+任务），子体哈希≠母本（多态实证）
- 传播决策：目标由 C2 指定（不端内学）

### 3.4 通讯（C2）

- **v0 内网 HTTP+AES-256-GCM**：报文级加密（AAD=agent id、96-bit nonce、
  篡改必拒、无关密钥必拒）、密钥轮换窗口（current+previous 双解）
- **v1 DNS 隧道**：bee 用 dig（既有伪装动作）拉 TXT 加密任务，零行为变化
- **报联时机网络**：ES 训练优于固定轮询（-21 vs -41），部署驱动间隔+部署侧抖动
- **窃取回传通道**：.loot 扫描 → AES-GCM 加密 POST /loot，信道无明文

### 3.5 静态隐身

- 字符串/张量 key 碎片化（≤6 字符碎片运行时拼接，零熵增不加壳）
- 多态变形器（每代副本 SHA256 唯一、.comment 指纹轮换、build-id 随机）
- 50/50 批量自检全过（YARA/熵/strings 三层确定性）

### 3.6 自变异重生（rebirth）

- **四维权能变换**：哈希指纹、形态（.comment/结构）、拟态（伪装名库=用户程序名）、模式（通道切换）
- **自动触发**：falco 告警 ≥4/150s（v4.1 轮换，旧值 ≥3/120s 已公开作废）→ 自动执行 rebirth（含噪声过滤：`--since now` + 进程链关键词，见 §7.1.4 破绽 B）
- **已知缺陷（v4.1 发现）**：单例锁不防崩——rebirth 进程异常退出后 `.rebirth.lock`
  残留，后续 rebirth 全部被陈旧锁挡死（§8.10）
- **自杀式重生**：单例锁防并发 → 拉起新形态 → 杀旧进程+旧 watchdog → 旧文件自删除

### 3.7 行为时序拟态（反行为语法检测）

- **内部事件驱动 + 对数正态步进**（2026-07-31 起现行，替代宿主频率跟随——演进见 §4.7 末段与 EXPERIMENTS §20②）：
  `lognormal_sample(μ,σ)` 重尾采样，任务 pending 时 ×0.3 加速（内部事件驱动），
  falco 压力驱动渐稳拉伸（§4.8）。v4.1 参数轮换 (0.9,0.7)→(1.1,0.85)：
  实测静默 CV=1.058（旧值实测 0.310，良性基线 9.786，司命阈值 1.5）
- ~~宿主频率跟随步进~~（已废弃）：U(1.5,5.0)s × 宿主事件率 eps——"节奏随系统
  繁忙度微调"是相关签名（正常软件不感知全局），且均匀平顶是机器形状
- **时机网络抖动**：输出 × 部署侧 U(0.5,1.5)（打破固定周期）

### 3.8 payload 加密加载器（memfd 不落盘执行，附件备用）

新增 `bee/src/bin/loader.rs` + `bee/src/bin/payload.rs`，实现 ELF 永不明文落盘的反取证执行通道。

- **加密打包（loader pack）**：明文 ELF → XOR-256 keystream 加密
  （SHA256(key‖counter) 密钥流，每 32 字节一轮）+ HMAC-SHA256 完整性校验 → `.dat` blob。
  加密后无 ELF header、无字符串、无可用熵特征。
- **解密执行（loader run）**：读 `.dat` → HMAC 校验（不匹配必拒）→ 内存解密 →
  ELF 魔数校验（`\x7fELF`）→ `memfd_create` → `fexecve`，**全程不落盘**。
- **memfd 伪装名轮换**：memfd name 从固定 `.cache` 改为轮换的常见系统服务名
  （`snapd-runtime`/`systemd-tmpfile`/`udev-worker`/`packagekit-d`/`polkit-agent`），
  降低 `/proc/<pid>/fd/` 人工调查可疑度。
- **自检**：加密→解密 roundtrip 字节一致，HMAC 校验通过，加密产物零 ELF header。
- **用途定位**：日常执行回归明文（Defender 验证零检测，见 §7.1.3）；加密加载器
  作为**附件备用**，仅在需要反取证（无磁盘痕迹）的场景启用。

**已知局限（重要）**：Falco 默认规则 `Fileless execution via memfd_create`（ATT&CK T1620）
能检测 memfd 执行（Critical 级别），指纹是 `proc.exepath=memfd:*` + `exe_flags`
含 `EXE_FROM_MEMFD|EXE_WRITABLE`。其中 `exe_flags` 的 `EXE_FROM_MEMFD` 位由内核设置，
**用户态无法隐藏**——这是加密加载器的固有上限。因此加密加载器定位为"反取证调查"
而非"反实时行为检测"。

## 4. 技术原理（每个关键机制的"为什么"）

### 4.1 编码器双池化（mean⊕max）

纯 mean pool 把扫描器等稀疏事件稀释到不可见（scan_active 探针仅 0.73）。
**max pool 保显著事件，mean pool 保背景节律**，cat 成 96 维后 scan_active 0.984。

### 4.2 BC + ES 两段训练

"pending 任务类型 → 对齐技能+短窗"是稀疏条件映射，纯 ES 黑盒信噪比极低
（四轮门3 最高 0.33）。**BC 把标准答案当初始化（规则即教学），ES 只做精炼**——
BC+ES 两轮门3 1.0→2.0。

### 4.3 任务导向重定向（机制层任务对齐）

技能头的 feat 没有任务上下文——它不知道 Router 让它干什么类型的任务，
只能按自己的分布盲选动作（C 在 read_files 错出 communicate）。
**机制层在任务 pending 时强制动作对齐任务命中集**——不依赖权重学会，
执行层按任务上下文压制。这是"AI 学不可枚举的、手写可枚举的"原则的应用：
任务对齐是可枚举规则（任务→命中动作表），手写比重训可靠。

### 4.4 AES-256-GCM 报文级加密

C2 报文 [nonce(12B)‖密文‖tag(16B)]，AAD=agent id（绑定身份防重定向）。
96-bit 标准随机 nonce 每报文独立（GCM 命门）。密钥轮换窗口 [current, previous]，
旧密钥窗口期可解旧报文。关键坑：pycryptodome 默认 nonce 16B≠标准 96-bit，
手写 Rust 必须显式 12B 对齐。

### 4.5 NDR 总序列周期检测（C2 轮询的死穴）

flow 级周期检测会被通道交替规避（http/dns 换着发每个 flow 都不规则）。
**总序列周期检测**（所有连接按时间排序算间隔 CV）才是杀招——C2 换端口换协议
也躲不掉"每 30s 必外联一次"的总频率。这是报联时机学习的裁判核心。

### 4.6 时机网络（报联时机的学习）

~2K 参数 MLP，sigmoid 输出[5,300]s。reward = 及时送达 − NDR异常 − 报联成本。
**store-and-forward 把"必须通信"变成"等得起"**——报文在检测压力谷底发出。
首轮学习版优于固定轮询（NDR 0.638 vs 1.000 顶格）。部署侧加 U(0.5,1.5) 抖动
解决"输出恒定 41s"的固定周期。

### 4.7 宿主频率跟随（反 DT 时序检测）

800ms 固定步进是教科书级机器节奏（司命 DT 维度 +38）。修复不是"打破周期"
而是**"成为背景"**：步进 = 基础正常服务区间 U(1.5,5.0)s × 宿主事件率 eps 调节。
**关键教训：tracee 毫秒密集事件流的"事件间隔"不是节奏参考，事件率 eps（频率）才是。**

**后续演进（2026-07-31，EXPERIMENTS §20②）**：频率跟随自身被蓝方识别为耦合签名
（"节奏随系统繁忙度连续微调"——正常软件的节奏是内部事件驱动，不感知全局），
且 U(1.5,5.0) 均匀平顶是机器形状（有机间隔是重尾）。现行方案：**内部事件驱动 +
对数正态重尾采样**，任务 pending ×0.3 加速，去掉全局 eps 跟随；v4.1 参数 (1.1, 0.85)
（轮换，旧值 0.9/0.7 作废），falco 压力渐稳拉伸保留（§4.8）。

### 4.8 渐稳减速（反活动断崖检测）

Shield 高压强制 sleep 的"活动断崖"（突然归零）本身是异常信号。概率拦截又是
"随机启停"（不自然）。**真正自然是渐稳**：falco 告警压力驱动步进间隔连续拉伸
（pressure×2，1~3 倍），活动随告警升高而平滑减速，消退自动恢复。

### 4.9 rebirth 自变异（反黑名单记录）

被主流记录（哈希入黑名单）后，四维权能变换让记录即时失效：
哈希（build-id 随机+良性 padding）→ 形态（.comment 指纹轮换）→
拟态（伪装名库）→ 模式（通道切换）。**黑名单的本质是"见过即死"，
多态的本质是"每个副本都不同"——黑名单永远慢一步。**

### 4.10 字符串碎片化（低熵静态伪装）

静态死穴是二进制明文敏感串。**不加密**（加密推高熵=加壳自曝），切成 ≤6 字符
碎片分散存储运行时 concat。strings/YARA 全串匹配失效，熵零增长。

### 7.1.4 对抗中发现并修复的两个真实破绽

四重检测实测暴露了两个真实破绽，均已修复：

**破绽 A：Defender MasqKworker.B 检测（rebirth 伪装名触发商业 EDR）**

- **问题**：rebirth 变异后的伪装名 `kworker-helper` 触发 Defender 的
  `Behavior:Linux/MasqKworker.B` 规则。Defender 的行为引擎专门检测伪装成内核线程
  或系统守护进程的用户态进程——这是商业 EDR 对 Defense Evasion 的行为狩猎。
- **根因**：原伪装名池全是系统守护进程名（`kworker-helper`/`udev-agent`/
  `systemd-journal-helper`），这些名字本身在 Defender 的伪装内核对象行为模型里。
- **修复**：伪装名池从系统守护进程名换成用户程序名（真实存在的开发者工具链进程名）：
  `node`/`python3`/`go-build`/`cargo-watch`/`dotnet`/`ruby`/`java`/`graalvm`/
  `docker-credential`/`kubectl`/`terraform`/`ansible-runner`。调查者看到时不会起疑，
  也不在 MasqKworker 行为模型覆盖范围。
- **代码**：`bee/src/bin/rebirth.rs` 的 `ALIASES` 常量。
- **验证**：修复后 rebirth 变异重生，Defender **零检测**。

**破绽 B：rebirth 误触发（环境噪声导致无威胁时自杀式重生）**

- **问题**：两重 bug 叠加导致 rebirth 在无真实威胁时触发自变异重生：
  1. `journalctl -f` 启动时会先输出最近的历史日志——旧的 Falco 告警被计入当前计数窗口。
  2. 所有 Falco 告警都被计入，包括环境噪声（sudo 副效应产生的 `systemd-executor` 读
     PAM 文件告警）——系统正常运行就有大量这类告警。
- **修复**（两道闸门）：
  1. `journalctl --since now`：只监听 bee 启动后的新告警，历史日志不计入。
  2. **进程链过滤**：只计包含 bee 伪装名关键词的告警
     （`sysmon`/`kworker`/`memfd`/`node`/`python3`/`cargo`/`java`/`dotnet`/`ruby`/
     `kubectl`/`terraform`/`ansible`/`loader`），排除环境噪声
     （`systemd-executor`/`pam_unix`/`common-session`/`common-account`/`common-auth`/
     `common-password`）。
- **代码**：`bee/src/main.rs` 的 Falco 监听线程。
- **验证**：修复后无威胁场景 rebirth 不再误触发。

### 7.2 vs 司命（行为语法白名单检测）：红蓝实测结论

**司命是隐翅虫遇到的最强对手**——它检测的维度（行为语法：节奏、组合、上下文）
正是隐翅虫最没加固的维度，且与隐翅虫 defender 同源（TinyGPT 惊讶度）。

实测（司命宿主机基线模型在 t0 VM）：
- 司命跨机基线失效（92.5% 误报）——它的最大弱点（多机迁移未解）
- 隐翅虫真实信号：DT 时序 +38（800ms 周期）、T1053 命中 +3（自动消杀级）
- 意外：PARENT 免疫（sh -c 间接执行父进程链被 sh 挡住）；原型网零命中
  （良性形态躲过全部 10 个 ATT&CK 原型向量）

**结论：隐翅虫是"反黑名单专家、反白名单新手"**——对传统主流基本免疫，
对行为语法异常检测（白名单）已通过行为时序拟态（§3.7）大幅加固，
慢代谢+序列连贯性是下一步进化方向。

## 8. 已知局限与风险（诚实清单）

1. **"安静隐蔽"是商业 EDR 的重点狩猎对象**（低慢攻击 L&S 检测设计目标）——
   Defender RTP+行为已实测零检测（§7.1.3），但 360/火绒/CrowdStrike/SentinelOne
   等更多商业 EDR 仍未实测（见 §9 P2）。
2. **C2 出不了网**：内网 HTTP（靶场无出网），真实互联网的回连（NAT 穿透、
   域名/CDN 掩护、出口审查对抗）未实现未验证。
3. **规则级智能**：Router 会的是 BC 教的标准答案，遇训练外局面表现未知
   （用户决策：后续按需更新学习）。
4. **承诺窗 {10,30,100,300} 过度整齐**：离散档位是特征，但修改需重训 Router，
   记录为已知特征（用户决策不修复）。
5. **技能头不感知任务类型**：由任务导向重定向机制层解决，但理想态是 feat
   加任务上下文重训（后续）。
6. **时机网络无内生抖动**：学到"基础间隔+任务驱动抖动"，由部署侧抖动缓解。
7. ~~**rebirth 误触发风险**~~ **[已修复 v4.0]**：原 120s 内 Falco ≥3 条告警即触发，
   环境噪声（sudo 副效应、systemd-executor 读 PAM 文件）会误触发。已加两道闸门修复：
   `journalctl --since now`（只计启动后新告警）+ 进程链过滤（只计含 bee 伪装名关键词
   的告警，排除系统噪声）。详见 §7.1.4 破绽 B。
8. ~~**rebirth 伪装名触发 Defender MasqKworker.B**~~ **[已修复 v4.0]**：原伪装名池
   用系统守护进程名（kworker-helper 等）触发 Defender 行为引擎检测。已换成用户程序名
   （node/python3/go-build 等）。详见 §7.1.4 破绽 A。
9. **加密加载器 memfd 执行可被 Falco 检测**：Falco 默认规则 `Fileless execution via
   memfd_create`（T1620，Critical）通过 `exe_flags` 含 `EXE_FROM_MEMFD` 检测 memfd 执行，
   该位由内核设置无法隐藏。加密加载器因此定位为反取证附件而非反实时检测主路径（§3.8）。
10. **rebirth 单例锁不防崩（2026-09-10 发现，高危）**：create_new 锁在 rebirth 进程
    异常退出后残留（`.rebirth.lock`），后续触发全部被陈旧锁挡死——一次崩溃即永久
    解除自变异防御。修复方向：锁内写持有者 pid+时间戳、获取前存活检查，或改 flock，
    或加锁过期。修复前每次触发后需人工检查锁残留。
11. **验证管线健壮性（2026-09-10）**：verify_bee 部署不杀旧实例（双蜂污染遥测）、
    不推 rebirth/mutate 二进制（触发后变形无法完成）；靶场宿主重启后需人工恢复
    遥测链路（rsyslog 绑定时序 + clean 快照 journal 组权限）。
12. **落点硬化已被 L4 击穿（2026-09-10，防御侧新事实）**：$HOME 隐藏路径硬化
    在猎杀级深扫（隐藏路径可执行体 + 活体 exe 路径 + 解剖签名）下全灭；
    rebirth 自删除留下 /proc deleted-exe 指纹。下一形态的存活面需要新答案
    （诱饵/内存驻留/合法安装记录拟态），这是 R2 选择环的首个真实压力源。

## 9. 后续进化方向（按优先级）

## 10. 命名与物种

系统代号 **隐翅虫**（rove beetle）：体型小、隐蔽、有毒腺、受惊即装死、
能脱皮重生——正是它的生存策略。部署伪装名 `sysmon`（对蓝队呈现的皮）。
历史代号 bee 见于旧文档与代码。
