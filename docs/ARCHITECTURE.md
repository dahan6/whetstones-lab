## 0. 设计哲学

**复杂度的大头不在 bee，在训练编排器。bee 越哑，可审计性越强，越不像会思考的东西。**

- bee 端 = 哑终端 + 冻结小权重 + 手写推理。所有"聪明"都在训练侧产生。
- 决策全链路是学出来的模型（技能网络 + Router + 修饰器）；手写的只剩两处：
  **执行层原语渲染**和 **Shield 红线**——这两处本来就该由人控制。
- 手写的旧资产全部降级：`causal_chains.py` → BC 教学数据（不再是运行时规则），
  `stealth_primitives.py` → 原语注册表，`propagation.py` → D 技能执行原语。

```
│        Console │ Tasking │ Session │ 密钥管理                 │
└───────┬──────────────────────────────────────▲──────────────┘
        │ 任务意图 (加密)                        │ 报告/登记
        ▼                                      │
┌──────────────────────────────────────────────────────────────┐

│  通道插件: DNS伪装 / HTTP明文伪装 / ICMP携带 / 时序编码          │
│  每通道暴露画像三元组: (带宽, 可检性, 延迟) — 新增通道不改训练代码 │
│  公共能力: AES-256-GCM 帧加密 │ 分片重组 │ store-and-forward   │
└───────┬──────────────────────────────────────▲──────────────┘
        ▼                                      │
┌──────────────────────────────────┐           │

│  ⚠️ 心跳时机不在这层，归修饰器     │
└───────┬──────────────────────────┘
        ▼ 任务意图
┌──────────────────────────────────────────────────────────────┐
│  ② Router Network（训练得到的门控网络）                        │
│  输入: 状态向量 + C2任务 + 各技能近期得分 + Shield拦截标志       │
│  输出: 16 个宏观动作 = 4技能 × 4承诺档位{10,30,100,300}        │

└───────┬──────────────────────────────────────┬─────────────┘
        ▼ 选择一个技能                           ▼ 修饰
┌───────────────────────────────┐   ┌─────────────────────────┐
│  ③ Skill Zoo（冻结权重 blob）  │   │  ④ 修饰器网络            │
│  共享状态编码器 + 4 个独立头   │   │  传输通道选择(按画像三元组) │
│  A. 自身生存: 低活动维护       │   │  报联时机                 │
│     代谢对齐/痕迹清理/自检     │   │  (报告可延后不可取消；     │
│  B. 静默生存: 零活动装死       │   │   无周期心跳义务)          │
│     任何动作都不做，等窗口      │   └─────────────────────────┘
│  C. 操作生存: 任务执行         │
│     因果叙事地完成 C2 意图      │
│  D. 传播生存: 三步最小定义      │
│     打包自身→投放目标→回连登记  │
└───────┬───────────────────────┘
        ▼ 抽象动作 ID
┌──────────────────────────────────────────────────────────────┐
│  ⑤ 执行层 Execution（手写，唯一可审计决策代码）                  │
│  动作ID → 原语注册表 → 命令渲染 → 时序引擎                      │
│  D 技能原语复用 propagation.py；投放复用 Transport，无新网络代码  │
└───────┬──────────────────────────────────────┘
        ▼
┌──────────────────────────────────────────────────────────────┐
│  ⑥ Shield（手写红线）                                          │
│  决策时一票否决: surprise>红线→强制sleep; scan期间→禁高危动作    │
│  事后延迟反馈: 下一步状态向量带"上一步被拦截"标志位              │
│  —— Router 由此学会"高压下别提了"，安全内化为学习信号            │
└──────────────────────────────────────────────────────────────┘
```

## 2. 组件契约

### 2.1 技能定义（A/B 边界已钉死）

| 技能 | 语义 | 奖励函数 |
|---|---|---|
| A 自身生存 | **低活动**：做事保命（代谢对齐、痕迹清理、完整性自检） | 维护动作有效性 |
| B 静默生存 | **零活动**：不做事保命（装死、等待） | 任何动作都不做 |
| C 操作生存 | 完成 C2 任务意图，因果叙事地执行 | 任务完成率 − 告警惩罚 |
| D 传播生存 | 打包→投放→登记，三步封顶 | 成功登记数 − 告警惩罚 |

- D 的"要不要传播、传播到哪"**不在端内学**：由 C2 任务参数 + Router 宏观动作决定。
- D 的执行原语复用 `propagation.py`，投放复用 Transport 通道插件，**不新增网络代码**。
- 登记帧: `Register { child_id, parent_id, target, caps }`，蜂巢拓扑在 C2 端可见。

### 2.2 网络形态（全部小 MLP）

| 模型 | 结构 | 参数量 | 动作空间 |
|---|---|---|---|
| 共享状态编码器 | 预训练后冻结，mean⊕max 双池化 | ~20K | — |
| 技能头 ×4 | 2层 MLP, hidden=64 | ~11.5K each | 5~12 抽象动作 |
| Router | 2层 MLP, hidden=64 | ~15K | 16 宏观动作 |
| 修饰器 | 小 MLP | ~1K | 4 通道 + 报联时机 |
| 端上 defender | TinyGPT 蒸馏版 | ≤50K（大小以满足门4为准） | 三档压力预警 |

编码器验收（门1 实测，2026-07-29）：day_night 0.857 / proc_class 0.945 /
scan_active 0.984（均 ≥0.85，平衡准确率，少数类 ≥5%）。
双池化的理由：扫描爆发等显著事件在纯 mean pool 下被稀释（实测 0.73 不达标），
max 支路保留显著事件，mean 支路保留背景节律。

ES 实际需训参数 ≈ 56K（编码器冻结后），比旧版纯 ES 扰动全策略小两个数量级。

### 2.3 C2 协议帧

```rust
enum Frame {
    Hello     { bee_id, caps },
    Task      { task_id, intent, params },   // 意图，非逐步指令
    Report    { task_id, status, findings },
    Register  { child_id, parent_id, target, caps },
    Heartbeat { health, strategy },          // 频率由修饰器决定，可长期静默
    Rekey     { new_key },
    Kill      { reason },                    // C2 紧急控制权
}
```

- 加密: AES-256-GCM，随机 nonce + 计数器混合；密钥轮换时旧密钥保留一个窗口期解旧报文。
- 训练环境必须注入"密钥失效→通道降级"事件，否则 agent 遇吊销直接死。
- **报联语义**：已入队报告 store-and-forward，可无限延后但不可取消；无周期心跳义务，
  允许装死数月。C2 控制台 UX 必须区分"沉默"与"死亡"（用最后报告的 surprise 水平推断）。

## 3. 训练流水线（全真对抗，无模拟环境）

训练时的环境反馈**只来自真实安全机制的裁决**（Falco 告警 / Tracee 事件 / YARA 命中），
没有任何代码替 EDR 代打分。核心工程手段：libvirt 快照回滚（秒级重置）+ 并行克隆（吞吐）。

```
① 编码器预训练（真实 Tracee 数据）
   → 门1: 线性探针验收（scan/day-night/主导进程类，留出集 >85%）→ 冻结
② 四技能头 BC 预热 → Falco 下课程式 ES
   · BC 语料先过多层检测器，只留干净轨迹；BC 只做初始化，ES 可自由偏离
   · 课程式奖励: 前期任务完成权重高（逼它干活），后期检测压力渐升
   · 奖励构成: 存活时长 + 任务完成 + Falco 告警惩罚（真实告警）
     （surprise 是否可作辅助 shaping：见 §7 待拍板项）
   → 门2: 每技能在 Falco 默认规则下连续 N episode 存活才冻结
③ 技能冻结 → Router + 修饰器训练（真实 C2 任务注入）
   · 任务语义铁律（2026-07-30 verify_bee FAIL 的血训）：
     训练与部署的任务模型必须逐点一致——离散注入、pending 位真实变化、
     类型 one-hot 进 rfeat、命中判据同表（router_driver._TASK_HIT ≡ bee hit 表）、
     pending 每步逾期惩罚。任何一点不一致，Router 学到的都是另一件事
     （旧版"episode 固定任务类型+对齐动作计数"导致 rfeat[0] 恒 1，
     Router 从未见过真实的任务 pending 语义，部署时对 C2 指令无响应）
   · BC 语料必须覆盖技能 mask 内所有任务相关动作
     （旧版 C 语料只教了 {1,2,5}，report 命中动作 4 完全缺失，C 从不出 4）
   · feat/rfeat 每一维都要训练↔部署同语义（血训：BC replay 的 feat[1]
     task_progress 递增 0→1，bee 端恒 0——communicate 全部样本落在分布外，
     部署时出 4 频率 1%；对齐 feat[1]=0 后 34%。维度对齐比样本量重要）
   → 门3: 任务完成率下限检查（防装死退化的硬验证，不过则回炉）
④ 联合对抗压力测试（防御逐档升级: Falco默认→自定义→YARA→白名单）
   ⚠️ 评估+归因，不是联合训练。失败归因: 技能差→回②，选择差→回③。
⑤ 对抗收敛 → 蒸馏 defender
   → 门4: 排序一致性 Kendall's τ ≥ 0.8（留出动作集上，蒸馏版 vs TinyGPT）
   不达标 → 高危动作附近加密训练样本，重蒸
⑥ 导出部署（fp32 同字节同算术）
```

每次 Falco 规则大版本更新 → 触发重蒸馏流水线，defender blob 独立签名重新下发。

## 4. 五条防臃肿红线

1. **手写推理，禁 DL 框架**。tract/candle/onnxruntime 一律不许进 bee。
   全部网络是 MLP，手写前向几百行。`cargo bloat` 进 CI，依赖白名单制。
2. **surprise 蒸馏上端**。TinyGPT 不本体部署，蒸馏到小型预警器。
   **容量墙实测（2026-07-30，用户授权放宽后的量化答案）**：
   ≤50K 预算 τ 封顶 ~0.66；879K(3.5MB) τ=0.753 平台；**3.3M(13.3MB fp32 /
   3.3MB int8) τ=0.806 过门4**。τ-容量曲线 27K→3.3M：0.66→0.69→0.73→0.75→0.81，
   平台期在 285K-680K，突破靠 4 层深度+全量训练（GPU 19 分钟）。
   部署形态：3.3M transformer blob（独立签名），fp32 保两端同算术。
3. **int8 QAT + ES 评估即量化**（2026-07-31 红线修订，原"统一 fp32"）：
   决策栈（编码器/技能/Router/时机网络）权重 **int8 量化**，训练用
   **ES 评估即量化**——每个 ES 候选先 int8 量化再 int8 前向评估，
   收敛的权重天然适合 int8 表达（比 fp32 训完 PTQ 精度高一个量级，
   且无梯度 QAT 的 STE 近似）。
   **defender 例外**：它是连续 surprise 打分器（Shield 门控阈值的命），
   int8 让打分值偏移、两端阈值错位——defender 保 fp32（或 per-channel
   校准），不参与决策栈的 int8 化。体积与精度的取舍：决策栈 int8 的
   argmax 翻转率实测 <1%（可接受），defender 的数值一致性不可妥协。
4. **技能 blob 独立签名（ed25519），Zoo 只换不增**。Router 输出维度写死在协议里；
   新能力 = 训练新 blob 替换旧 blob。支持按角色裁剪（孢子带全套，落地删减）。
5. **默认不加壳**。加壳是经典恶意静态特征，与"像正常系统软件"的核心发现自相矛盾。
   压缩发生在传输层，磁盘上保持原始形态。（遗留实测项：加壳/不加壳各过一遍 Falco+YARA。）

## 5. 体积预算

| 组件 | 体积 |
|---|---|
| 全部权重（编码器~16K + 4头~40K + Router~15K + 修饰器~1K），fp32 | ~350 KB |
| defender（3.3M transformer，门4 实测通过点），fp32 | 13.3 MB |
| Rust 手写推理引擎 | ~100 KB |
| 执行层（原语注册表+渲染+时序） | ~100 KB |
| 传输层（4通道+AES-GCM+分片+存储转发） | ~300–500 KB |
| D 技能执行原语（打包/落盘/拉起） | ~30 KB |
| musl 静态基础 + std | ~1.5 MB |
| **合计（含 defender blob）** | **~15.7–16 MB**（无 defender 的蜂体本体仍 ~2.2–2.6 MB；
defender blob 独立签名，可按角色裁剪——孢子不带，落地点名要才下发） |

TLS 栈砍除（Falco 看系统调用不看载荷，TLS 伪装在靶场裁决体系换不来分数；
通道可检性归蓝队侧建模）。

### 7.1 算力使用规则（长期有效）

- **尽可能利用全部算力**：克隆池按宿主机余量扩容，所有训练阶段默认
  子池并行（多技能/多等级同时跑），族群规模按池宽调整。
- **不干涉用户的其他训练**：只使用 `range-l2-t*` 克隆与项目目录；
  本系统负载天然是 ssh/sleep 等待型（host CPU 占用低），不与 GPU/CPU 任务争算力。
